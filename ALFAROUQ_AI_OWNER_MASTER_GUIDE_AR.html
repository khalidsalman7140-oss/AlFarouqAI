1. الرؤية والواقع

واجهة موحدة خفيفة مع محركات اختيارية، خدمات جاهزة تحتاجها الدراسة والعمل، ونتائج وتتبع مصادر قابلين للتصدير. الرؤية واسعة؛ التنفيذ الحالي مجموعة محدودة معلنة من القدرات لا «كل AI»، ولم تُثبت الأفضلية أو دقة سوقية/سريرية/صناعية. حافظ على مبدأ: لا adapter يسمى استدلالاً مختبراً إلا بعد تشغيل أوزان وبيانات فعلية.

2. مسار التنفيذ والواجهات

AI يمر إلى Client أو model_call حين model صريح؛ Client.plan يختار عبر قواعد محافظة بالعربية/الإنجليزية، Client.run يتحقق من Capability والحدود وينفذ handler ثم Result(data/backend/warnings/provenance). النموذج الافتراضي للنصوص صغير ومحلي؛ لا وكيل غير محدود للأوامر. Model جلسة إعادة استخدام. Config حاوية إعدادات؛ مررها صراحة، ولا تعدّل حقولها بالتوازي بين المهام دون ضبط التزامن ومراجعة core.py. Registry نقطة إضافة القدرات، وentry-point plugins كود موثوق لا يُحمّل عشوائياً. مثال خدمة: دالة keyword-only تستقبل config وتعيد Result؛ سجلها في services أو extensions واكتب اختبارات واضحة. Registry.register وCapability توقيعاتهما أدناه. كل الملفات الحالية وتعليقات وحدات الكود وتواقيعها موضحة لاحقاً من AST الحقيقي.

3. الأمان والموارد والتخزين

افتراضات Config: no network، no remote، no model download. الموافقة لا تعني صلاحية استخدام البيانات. endpoints في providers/engines تضبط HTTP والهوست؛ راجع أي توسعة ضد SSRF وredirect وتسريب المفاتيح. لا اعتبار run trusted code كـsandbox. Atomic writes ترفض overwrite افتراضياً؛ راقب الملفات الحساسة وأذونات SQLite. VectorStore يخزن النصوص والembeddings في SQLite ويبحث FAISS، وليس تشفيراً أو إخفاء بيانات. RAG قد يهلوس؛ لا ضمان لصحة citation. لا ترسل document content إلى remote دون موافقة المستخدم. Model cache يسجل revision والأحجام والهاش؛ إعادة استخدام cache يتحقق من وجود/حجم لا full hash لكل استدعاء؛ راجع checksum خارجياً قبل الاعتماد على تحميل غير موثوق. لا remote Python code تلقائياً. resources.environment يقرأ system/cgroup/nvidia-smi إذا وجد. model_plan هامش تقريبي لا توزيع GPU أو تكميم أو budget KV cache. لم يجر قياس إنتاجي أو اختبار حمل.

4. البناء والتحقق وتكرار الإصدار

أنشئ venv مستقل ثم pip install '.[dev]' والإضافات المطلوبة حسب اختباراتك. نفذ python -m build وpython -m twine check dist/* ثم ثبّت wheel في بيئة نظيفة. python scripts/wheel_smoke.py --output ... من خارج checkout يفحص النواة. لتحقق النماذج والأجهزة البرمجية جهز ستة caches وTesseract eng/ara وespeak-ng و Mosquitto، ثم ALFAROUQ_MODEL_HOME=/your/cache python scripts/run_verification.py --installed. Windows env syntax يختلف؛ الاختبار هنا Linux فقط. لا تستعمل .venv ضخماً داخل ZIP. python scripts/verify_coding_guide.py --installed ينفذ نص كل مثال ويقارن task. python scripts/build_complete_guide.py يولد المرجع من نفس النص ونتيجة الاختبار. python scripts/build_docs.py يولد HTML أوفلاين. python scripts/prepublish_check.py فحص heuristic للأسرار والبنية لا ضمان تدقيق أمان؛ لا ترفع .git قديمة أو creds. python scripts/package_delivery.py ينشئ manifest وZIP ثم CRC/هاش؛ python scripts/validate_project.py --archive /path/to.zip يفك ويتحقق من كل ملف. أسماء الإصدارات في pyproject وcore.version يجب أن تتطابق. احتفظ بالمدخل الأصلي كأرشيف احتياطي منفصل، وليس رجوعاً فوق الكود الحالي. increment PEP440 قبل كل إصدار.

PyPI Trusted Publishing يتطلب إنشاء/امتلاك المشروع وإعداد بيئة GitHub وصلاحيات OIDC؛ اختبر TestPyPI أولاً بعد موافقتك. راجع PUBLICATION_GUIDE. Hugging Face/Colab/Kaggle قوالب إعداد، وليست منصات مرفوعة أو مصدقة الاختبار. Google Drive: scripts/upload_to_google_drive.py --help ثم OAuth Desktop credentials من حسابك ونطاق أقل صلاحية؛ لا تعطي مساعداً كلمة المرور. لا token.json في المصدر. AI Drive خدمة مختلفة؛ تحقق من رابط المستخدم لا temporary readable URL. لا يمكن تجاوز شاشة اشتراك مزود ببرمجة محلية. تسليم الهاتف يحتاج ملفاً صغيراً ورابطاً متاحاً.

7. اكتمال وحدود وخطة تطوير

النواة القديمة والميزات الإضافية مستمرة، والعد النهائي في reports/RELEASE_REPORT.ar.md. اختبارات حقيقية بأوزان صغيرة وقنوات برمجية لا تثبت دقة كل مجال أو مصنع أو corpus عربي واسع. توليد الصور/الفيديو وimage.objects القديم adapter-only غير مختبرين بأوزان في هذا الإصدار. استخدام compatible protocol لا يثبت vLLM/Ollama الأصليين. لا روبوت أو PLC مادي، لا ASR accuracy benchmark، لا fine-tuning ضخم، لا multimodal عام، لا dynamic automatic arbitrary-model downloading، ولا اختبار GPU/كل منصات cloud. المرحلة التالية: golden Arabic dataset، grouped/time split تقييم صيانة، قياس GPU/context وquantization، streaming/cancellation، اختبارات أحمال API، allowlist أقوى وremote isolation، تقييم RAG ضد prompt injection، regression للplatforms، وتثبيت الإصدارات المراجعة حسب مصفوفة كل نظام. لا توسع القائمة أسرع من قابلية اختبارها. عند خطأ قارن wheel/source/version والبيئة والـcache وسجل backend ثم أضف failing test قبل الإصلاح. limits ليست sandbox؛ لا تجعل مستخدمين غير موثوقين يشغّلون الخدمة على خادم ببيانات حساسة بلا عزل حقيقي.
