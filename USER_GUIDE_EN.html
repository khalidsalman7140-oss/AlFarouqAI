1. Purpose and learning path

A lightweight Python entry point for real text, data, vision, speech, document, model, agent, industrial and defensive tools. It reduces integration boilerplate and returns data, backend, warnings and provenance. It is not a universal model, a quality benchmark, a production safety certification or unlimited compute. Start with text and export; install an optional engine for your next project. Use explicit task names and model sessions for reproducible advanced work.

2. Install the delivered release

Python 3.10+ is targeted; actual release verification is Python 3.12/Linux/CPU. Unzip and enter the folder containing pyproject.toml. Do not assume a similarly named public PyPI package is this release; no public publication happened here.

python -m venv .venv
# Windows PowerShell: .\.\.venv\Scripts\Activate.ps1
# Linux/macOS: source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install .
python -m alfarouqai --version

Alternatively install the included dist/alfarouqai-0.3.0a1-py3-none-any.whl. The core has zero mandatory runtime dependencies. Add only what you need: python -m pip install '.[nlp,ml]' for Arabic text projects, '.[local]' for local text models, '.[torchvision,vision]' for pretrained vision, or '.[vector]' for semantic search. The authoritative extras are in pyproject.toml. OCR/TTS/MQTT may need Tesseract plus language packs, espeak-ng or Mosquitto from your OS. Import never installs packages, downloads weights or silently enables networking. A managed installer is opt-in and refuses to change the current interpreter.

3. First application, output and routing

Save this as app.py, run python app.py from Terminal:

from alfarouqai import AI, Client, Config
result = AI("حلل هذا النص", text="الذكاء الاصطناعي يساعد الطلاب.")
print(result.to_dict())
result.export("text-report.json")
client = Client(Config(verbose=True))
print(client.capabilities())

Result.data is the payload, backend identifies the engine, warnings state limits, and provenance records supported execution/source details. Export accepts JSON, CSV, Markdown, HTML and TXT, refusing overwrite unless explicitly approved. Config(verbose=True) writes start/done/backend/error type to stderr. Display or print results yourself in notebooks; not every external engine exposes a progress percentage. Use Client.plan before execution and Client.run for unambiguous tasks. Missing training targets, image references and device permissions are not guessed. A general text prompt may use the local LLM; this does not authorize arbitrary OS commands or make unsupported natural-language requests executable.

4. Models and resource-aware convenience

from alfarouqai import AI, Config, prepare_model, environment, model_plan, Model
print(environment())
print(model_plan(70, precision_bits=4).to_dict())
# Explicitly approves network + weights download; review license/storage first.
cfg = Config(allow_network=True, allow_model_download=True)
prepare_model("smollm2-135m", config=cfg)
result = AI("What is the capital of France?", model="smollm2-135m", device="auto", config=cfg)
print(result.to_dict())
# A reusable model avoids reloading for every call.
with Model("smollm2-135m", config=cfg, device="cpu") as model:
    print(model("Explain Python briefly.").data)

The download step requires your deliberate network/weight consent and the model's license. The small 135M test model is English-first and limited, not a strong Arabic assistant. The model registry stores revision/file manifests; no weights ship in this ZIP. Cache defaults to ~/.cache/alfarouqai/models; ALFAROUQ_MODEL_HOME overrides it. CPU inference and unavailable-CUDA rejection were tested; real GPU inference was not. Local model directories must be reviewed Transformers causal-LM safetensors models; arbitrary architectures and remote Python code are not automatically run. model_plan estimates weight memory and a rough margin, not context/KV/batch fit, quantization support or multi-GPU deployment. Use smaller weights or an appropriate server when resources are insufficient. Model with/close releases reusable sessions.

5. Hosted and local inference servers

from alfarouqai import AI, Config
# Requires your already running compatible inference server. Not a live-service test.
r = AI("Explain Python briefly.", model="YOUR_SERVER_MODEL",
       backend="compatible", endpoint="http://127.0.0.1:8000/v1",
       config=Config(allow_network=True))
print(r.data)

Use backend='ollama' with the appropriate endpoint for your running Ollama server. Protocol tests used a real-model reference server; the actual Ollama/vLLM daemons were not installed/exercised. Remote servers need HTTPS and explicit allow_network and allow_remote. Pass an environment-variable NAME with api_key_env; never put the secret value in code or Git. Server provisioning, supported models, permissions, license, GPU costs and rate limits remain your responsibility. No mandatory paid API.

6. Editors, notebooks, cloud and phone

VS Code: open the folder, select .venv through Python: Select Interpreter, run app.py. PyCharm: choose that same existing interpreter. Jupyter: install ipykernel into the chosen environment and select its kernel. Colab/Kaggle: upload the ZIP or wheel, unpack, %pip install /path/to/release.whl, and change into the source root for the examples' fixture helpers. Put tokens in notebook Secrets, save outputs before the ephemeral runtime ends and separately enable a GPU if needed. These are deployment instructions, not evidence of a tested platform matrix. Not every engine uses GPU. Hugging Face Spaces preparation is under deploy/huggingface; Codespaces can use the same Python setup subject to its host limits. Windows/macOS and cloud runtimes were not actually run during this local verification. On a phone, download/unzip and read HTML/Markdown, then use a browser-hosted Python runtime or your inference server; Android native PyTorch/TensorFlow installation is not an advertised tested path.

7. Service catalog and working projects

The complete coding reference at ALFAROUQ_AI_COMPLETE_CODING_GUIDE.md contains every registered capability, exact executed snippets, requirements and real output previews. It is bilingual in API/code; this English guide explains the surrounding workflow. Run python examples/guide/arabic_process.py from the root for a self-contained fixture example, then replace the fixture inputs with your own authorized data. All source snippets come from guide_catalog and are checked by verify_coding_guide. Fixtures are synthetic educational data, not patient records or real factory events.

Arabic coursework: normalize/tokenize/ISRI, train TF-IDF + LogisticRegression with an explicit text/label column, predict and persist, explore LDA topics and lexical similarity. Stemming is not contextual lemmatization; lexical TF-IDF is not semantic embedding. Deduplication alone does not prevent group/time/author leakage. Business: profile/clean/group CSV, monthly sales forecasting with temporal validation, content recommendations, Decimal ledger reconciliation. Forecasts are not guarantees, and reconciliation is not payment authorization or proven fraud detection. Manufacturing: sensor summaries, control charts using independent baselines, aligned reference-image inspection, labeled maintenance classifiers and production summaries. These are not universal defect detectors, remaining-useful-life estimators, OEE without necessary inputs, safety control systems or physical hardware validation. Developers: AST review, read-only SQLite schema analysis, generated code/test suggestions, a bounded API and trusted-code test execution. The subprocess runner is NOT a sandbox. Researchers: read/search documents, persistent multilingual vectors, grounded-answer attempts, source snippets and export. Validate answers yourself; provenance is not proof of entailment. Scanned PDFs need OCR preprocessing; not all pages auto-OCR. Institutions: appointment waiting-time/group analysis and approximate PII patterns; no clinical diagnosis, regulatory compliance or guaranteed anonymization is claimed.

Executed service block after the common setup below:

with broker() as port:
    def publish():
        import time
        time.sleep(.5)
        Client(Config(allow_network=True)).run('iot.mqtt.publish', host='127.0.0.1', port=port, topic='demo/readings', message='24', consent=True)
    thread = threading.Thread(target=publish); thread.start()
    result = Client(Config(allow_network=True)).run('iot.mqtt.read', host='127.0.0.1', port=port, topic='demo/readings', duration=4)
    thread.join()

robotics.serial

Exchange bounded data on a caller-approved local serial port

Extra: iot. Required: port.

serial_exchange(*, port, config, baudrate=9600, read_bytes=128, command=None, consent=False)

Executed service block after the common setup below:

import os, select
master, slave = os.openpty()
def device_side():
    if select.select([master],[],[],4)[0]:
        os.read(master,128); os.write(master,b'PONG')
thread=threading.Thread(target=device_side); thread.start()
try:
    result=Client(Config(timeout=2)).run('robotics.serial',port=os.ttyname(slave),command='PING',read_bytes=4,consent=True)
    thread.join()
finally:
    os.close(master); os.close(slave)

9. Troubleshooting and production boundaries

MissingDependency: install the relevant extra in the active interpreter. ConsentRequired: review/approve the requested network, model, code or device access. ValidationError: check files, columns and limits; UnsupportedTask: use explicit task. OOM: close models, isolate sequential workers or use a smaller model/remote endpoint. Timeout is not a universal CPU/RAM limiter. Do not run untrusted generated code; -I and subprocess timeouts do not isolate filesystem/network. Protect credentials, use HTTPS and review data transfer. Treat retrieved documents as untrusted data, not agent instructions. Review model/dataset licenses independently of framework licenses.

Scheduler needs tick; it does not keep running when the machine stops. AgentTeam is a bounded DAG and LLMAgent selects from an allowlist, not an unrestricted autonomous employee. MQTT delivery is not proof of device action. Serial/Modbus used local PTY/ servers only, not real robots/PLCs. API authentication and limits are a starting point, not a production security audit. Small-model outputs, ASR and vision can be inaccurate.
